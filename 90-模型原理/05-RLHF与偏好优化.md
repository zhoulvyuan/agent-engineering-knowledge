# RLHF / 偏好优化

> **状态**：🟢 已理解 ｜ **深度**：C 理解概念 ｜ **更新**：2026-09-15
> **上级**：[90-模型原理](README.md) ｜ **依赖**：Fine-tuning

## 一句话定义

> RLHF（基于人类反馈的强化学习）与偏好优化，是用"人类对多个回答的相对偏好"作为训练信号，去调整已预训练语言模型输出分布的一套对齐方法，让模型更倾向于生成人类更满意的回答。

## 解决的问题

> 预训练+SFT 之后的模型"会说话"但不一定"说人话"：目标函数是预测下一个 token 的似然，而不是"回答是否有用、无害、诚实"。很多期望（礼貌、拒绝有害请求、按指令格式回答、简洁或详尽）难以用一条明确的损失函数写出来，也难以靠人工标注"标准答案"穷举——因为好回答不唯一。人类更擅长"在两个回答中选更好的那个"而非"写出完美答案"。RLHF 把这种**相对偏好**转化为可优化的信号，弥补了"目标不可写成显式损失""标准答案不唯一""SFT 只学模仿、不学取舍"这几个麻烦。

### RLHF 解决什么问题

- 核心解决**目标难以显式定义**的问题："有用、无害、诚实"无法写成一行损失函数，但人类能对两个回答做相对判断。
- 把"难以书写的标准答案"替换为"易于采集的成对偏好"，再用奖励模型把离散偏好拟合成连续奖励，供策略优化使用。
- 补齐 SFT 的短板：SFT 只能模仿示范数据（学会"长什么样"），无法学会"在次优与更优之间取舍"（学会"哪个更好"），也无法惩罚坏输出；RLHF 提供了负向信号。
- 实现**可控的行为塑形**：拒答有害请求、遵循格式/风格、控制啰嗦程度等，都可以通过偏好数据注入。
- 工程视角：它是把"产品/安全团队的主观质量标准"规模化注入模型的通道，比逐条写规则或堆 SFT 数据更可扩展。

### 为什么需要人类偏好对齐

- 预训练目标（最大化语料似然）与人类真实意图之间存在**目标错配**：语料里"高频/流畅"不等于"有用/安全"。
- 好回答往往**不唯一且情境依赖**，没有唯一 ground truth，监督学习的"对一个标准答案算 loss"范式失效，而偏好比较天然适配这种模糊性。
- 人类标注成本结构决定了"选择题比问答题便宜且一致性更高"：标注员对 A/B 排序的一致性远高于让其独立写满分答案。
- 安全与合规是硬需求：需要显式地压低有害、越狱、幻觉等输出的概率，这需要负向偏好信号而非单纯模仿。
- 对齐还负责"人格与风格统一"，让同一产品下的模型表现一致、可预期。

### 对齐与能力之间的关系

| 视角 | 说明 |
| --- | --- |
| 能力来自预训练 | 知识、推理等底层能力主要在预训练阶段习得；对齐**不显著新增知识**，主要是"激发/调度"已有能力并约束表达方式。 |
| 对齐税（alignment tax） | 过度或粗糙的对齐会损害部分能力指标（如推理、代码、多样性），即用能力换安全/风格，称为对齐税。 |
| 二者可部分解耦 | "能回答"与"愿意按期望方式回答"是两件事；强模型若对齐差也会不可用，弱模型对齐再好也补不上能力。 |
| 工程取舍 | 实践中靠 KL 正则、混入 SFT/预训练数据、精调奖励模型来**在能力与对齐间找平衡**，而非单极最大化任一端。 |
| 当前共识 | 对齐是"放大器+护栏"，不是"能力来源"；想提升上限仍需更强的基座与数据。 |

## 核心内容

- **典型三阶段流水线（经典 RLHF）**：
  1. SFT：用高质量示范数据监督微调，得到初始策略模型。
  2. 奖励模型（RM）训练：对同一 prompt 采样多个回答，人类排序，用 Bradley-Terry 式成对损失训练 RM，使其对"更被偏好的回答"打更高分。
  3. 策略优化：以 RM 分数为奖励，用 PPO 等 RL 算法优化策略，同时加 **KL 惩罚**约束新策略不偏离 SFT 太远，防止"奖励作弊"和能力崩塌。
- **偏好数据**：核心资产是 (prompt, chosen, rejected) 三元组；质量、覆盖面、标注一致性直接决定上限。
- **KL 正则项**：奖励 = RM 分数 − β·KL(策略‖参考模型)，是防止分布漂移与模式崩塌的关键旋钮。
- **直接偏好优化（DPO）及其家族**：跳过显式 RM 与 RL，直接用偏好对上的闭式损失优化策略（DPO/IPO/KTO/ORPO/SimPO 等），工程更简单、更稳定，近两年成为主流替代。
- **在线 vs 离线**：PPO 属在线（训练中实时采样打分），DPO 属离线（固定偏好数据集）；在线能持续探索但更重，离线更省但受数据集覆盖限制。
- **反馈来源**：人类反馈（RLHF）之外，还有 AI 反馈（RLAIF，用更强模型或宪法规则代替部分人工）。
- **评估**：靠人类/模型评测胜率（win rate）、安全红队、能力基准三方面交叉验证，防止只优化了 RM 指标。

## 与其他知识的关系

| 关系 | 知识点 | 说明 |
| --- | --- | --- |
| 上游 | 预训练 + SFT（Fine-tuning） | RLHF 作用在已 SFT 的模型上，依赖其提供的基础能力与初始策略/参考分布；没有像样的 SFT，RLHF 很难稳定收敛。 |
| 下游 | 对齐后的 Chat/Instruct 模型与推理部署 | RLHF/DPO 产出的是面向用户的对齐模型，直接进入 prompt 工程、RAG、Agent 等上层应用，并作为后续安全加固的基线。 |
| 易混淆 | SFT vs 偏好优化、PPO vs DPO、RLHF vs RLAIF | SFT 是模仿唯一示范、偏好优化是学相对好坏；PPO 需显式 RM+在线采样、DPO 用成对数据闭式优化；RLHF 用人类反馈、RLAIF 用模型/规则反馈。 |

## 典型工程场景

- 通用对话助手上线前的"最后一公里"对齐：让回答更有用、更守格式、更礼貌。
- 安全与合规加固：批量注入拒答有害/越狱请求、减少幻觉与不当内容的偏好数据。
- 产品化风格统一：固定人格、语气、详略程度（如客服简洁、法律严谨）。
- 领域/企业定制：用业务专家的偏好数据把模型调成符合内部标准（如代码规范、医疗问诊话术约束）。
- 指令遵循与格式约束：让模型稳定输出 JSON、Markdown、特定模板。
- 以 DPO/KTO 做轻量迭代：在无 RL 基础设施的团队用成对/点赞点踩数据快速迭代对齐。

## 适用边界

**适合使用**

- 已有不错的基座+SFT 模型，需要在"行为/风格/安全"上做精细塑形。
- 目标难以写成明确标准答案，但人类能做相对好坏判断。
- 能持续采集高质量偏好数据（人工或线上点赞点踩）。
- 需要显式压制某类输出（有害、越狱、幻觉）并提供负向信号。

**不适合使用**

- 想靠它"补知识/补能力"：对齐几乎不新增知识，应回到预训练/继续预训练/检索。
- 偏好数据稀缺或噪声大、标注标准不一致——会放大噪声、训崩或奖励作弊。
- 任务有明确唯一答案（分类、抽取、带标准答案的数学）——直接 SFT/监督学习更高效。
- 团队无稳定评测与红队能力：无法判断"对齐税"与过拟合，容易越调越差。

## 常见误区

- 以为 RLHF 能提升模型智力/知识——它主要塑形行为，不是能力来源。
- 把 RM 分数当最终目标，忽视"奖励作弊"（模型学会讨好 RM 而非真正变好），忘了 KL 正则与独立评测。
- 认为 DPO 完全等价且总是优于 PPO——DPO 更简单稳定，但在线探索、复杂奖励、持续学习场景 PPO 仍有优势。
- 偏好数据越多越好——覆盖面与一致性比数量更重要，脏数据会直接污染对齐方向。
- 把 SFT 和偏好优化混为一谈——前者学模仿，后者学取舍，二者互补而非替代。
- 忽视"对齐税"——盲目追求安全/风格可能悄悄损害推理、代码、多样性等能力。

## 我的结论

> 当你已有一个"能力够用但行为不够听话"的 SFT 模型，且目标是**行为塑形**（有用/无害/风格/格式/安全），并且能拿到质量过关的偏好数据时，就该上偏好优化；基础设施薄弱时优先用 DPO 及其变体快速迭代，需要在线探索或复杂奖励时再上 PPO。
> 反过来，若问题是"模型不懂/能力不足"，或任务有唯一标准答案，或偏好数据又少又脏，就**不该**指望 RLHF——那是预训练、SFT 或检索该解决的事。一句话：RLHF/偏好优化是"护栏与放大器"，不是"引擎"；用它校准方向，而不是用它制造动力。
