# 12 实战项目

> 主线域 ｜ **知识验证场**。原地图完全缺失这一层。

## 为什么需要这个域

前面 11 个域回答的是"知识是什么"，本域回答的是"**我到底会不会**"。

知识库如果没有验证场，会出现一个隐蔽的问题：**知识点都在，但连不起来**。
你可能会解释清楚 ReAct 是什么，却在被要求"设计一个能处理工单的 Agent"时无从下手。

本域的作用就是**强制把知识连起来**。

## 项目记录规范

每个项目一个文件，建议包含：

```markdown
# 项目名称

> 状态 ｜ 起止时间 ｜ 用到的知识域

## 需求与约束
## 方案设计（含架构图）
## 关键决策与理由
    - 每个决策要写"我为什么选它、放弃了什么"
## 遇到的问题与解决过程
## 用到了哪些知识域（反向验证知识地图）
## 暴露出的知识缺口（回流到知识地图）
## 复盘：如果重做会怎么改
```

**最后两节是关键**：项目不是为了产出代码，而是为了**反向暴露知识缺口**，
让知识地图持续演进。

## 建议的里程碑项目

按学习路线，建议至少完成这 4 个，每个对应一个能力阶段：

| # | 项目 | 验证的能力 | 对应阶段 |
| --- | --- | --- | --- |
| 1 | 结构化输出服务 | Prompt / Structured Output / API 工程 | 阶段 1 |
| 2 | 带工具的问答应用 | Tool Calling / Context Engineering | 阶段 2 |
| 3 | **[关键] 单 Agent 应用** | Agent Loop / State / ReAct | 阶段 3 |
| 4 | 可评估的 Agent 系统 | Evaluation / Observability / Reliability | 阶段 5 |

> 第 3 个是**分水岭**：做完它，你才算真正进入 Agent 开发。
> 第 4 个是**从能跑到能用的分界线**。
