## 一句话定义

> LLM 是一个在海量文本上训练出来的、用来预测"下一个 token 最可能是什么"的巨型概率模型；它把语言规律和世界知识压缩进了几十亿到上万亿个参数里。

## 解决的问题

> 在 LLM 之前，每个自然语言任务（翻译、分类、问答、摘要……）都要单独设计特征、单独标注数据、单独训练一个模型，成本高、迁移难、通用性差。
> LLM 用"一个统一的预训练模型 + 少量提示/微调"就能覆盖几乎所有文本任务，把"为每个任务造一个专用系统"变成了"用一个通用模型做各种事"，大幅降低了 NLP 能力的落地门槛。

### LLM 本质上是什么

本质上它是一个**条件概率函数**：给定前面已经出现的一串 token，输出下一个 token 在整个词表上的概率分布，然后按某种策略（贪心 / 采样）挑一个，再把它拼回输入、循环往复。所谓"理解""推理""对话"，都是这个"逐 token 续写"过程在超大规模参数和数据下涌现出来的表象，模型内部并没有一个显式的知识库或逻辑引擎，只有一组被训练好的权重。

### 训练与推理的基本区别

- **训练（training）**：喂入大量文本，用"预测下一个 token"作为目标，通过反向传播不断**调整参数**，让预测越来越准。计算量巨大、耗时以周/月计、需要大规模 GPU 集群，是"塑造模型"的阶段。
- **推理（inference）**：参数已经**冻结不变**，只做前向计算——输入 prompt，一个 token 一个 token 地生成输出。相对轻量、实时，是"使用模型"的阶段。
- 一句话：训练是"写入知识与能力"，推理是"读取并运用能力"；训练改权重，推理不改权重。

### 模型能力从哪里来

- **预训练**：在超大规模、多领域语料上学习语言结构与世界知识，能力的"底子"在这里形成，规模（数据量、参数量、算力）达到一定阈值后出现**涌现能力**。
- **后训练 / 对齐**：SFT（指令微调）教会模型"听懂人话、按格式回答"，RLHF / RLAIF 等让输出更符合人类偏好与安全要求。
- **上下文（推理时）**：prompt、示例（few-shot）、检索到的资料能在不改权重的情况下临时"激活/引导"已有能力。
- 归纳：能力 = 预训练打底 + 后训练对齐 + 上下文临时引导。

### 模型为什么会产生幻觉

根因在于它的目标是"生成**流畅且高概率**的续写"，而不是"输出**真实**的事实"。具体成因：
- 训练目标只优化"像不像人写的",从不校验"对不对"；
- 知识以概率形式弥散在参数里，没有精确检索机制，细节（数字、人名、引用）容易被"编"得通顺却错误；
- 训练数据本身有错误、过时或覆盖不到的空白，模型会用最像的模式去填补；
- 采样带随机性，且模型缺乏可靠的"我不知道"信号，倾向于自信地给出答案。
- 缓解手段：RAG 引入外部可信资料、让模型引用来源、降低温度、要求给出不确定性、用工具核验。

### 模型能力与上下文之间的关系

上下文是**推理期激活能力的关键杠杆**：模型的"潜力"由权重决定，但"这一次到底表现出多少"很大程度取决于上下文。
- 好的上下文（清晰指令、相关示例、检索到的事实、结构化输入）能显著提升准确率与稳定性——这正是提示工程、few-shot、RAG 的价值所在。
- 但上下文有**长度上限**，且存在"迷失在中间"（长文中间信息被忽略）、注意力稀释等问题，信息越多不一定越好。
- 关键区分：上下文只能**调用和组织**已有能力，无法**新增**权重里根本不存在的知识或技能——想要新能力仍需训练/微调。

## 核心内容

- **架构**：主流 LLM 基于 Transformer，核心是自注意力机制（self-attention），让每个 token 都能关注序列中其他 token，从而建模长距离依赖。
- **Token 化**：文本先被切成 token（子词单元），模型的一切输入输出都以 token 为单位，也因此有"上下文窗口 = 多少 token"的限制和按 token 计费。
- **自回归生成**：从左到右逐个预测 token，每一步都把已生成内容作为新的输入。
- **关键调参**：temperature/top-p 控制随机性，max_tokens 控制长度，system prompt 设定角色与规则。
- **规模效应**：参数量、数据量、算力的增长带来 scaling law 式的性能提升，并在某些临界点涌现出小模型没有的能力（如多步推理、指令遵循）。

| 关系 | 知识点 | 说明 |

| 上游 | Transformer / 自注意力、Token 化 | LLM 的底层架构与输入表示 |
| 下游 | Prompt 工程、RAG、微调、Agent | 都是在 LLM 之上"用好/增强"它的手段 |
| 易混淆 | 传统 NLP 专用模型、知识库/搜索引擎 | LLM 是通用概率生成器，不是精确检索或事实数据库 |

## 典型工程场景

> - 内容生成：文案、代码、摘要、翻译、改写。
> - 对话与问答：客服机器人、知识助手（常配 RAG）。
> - 信息抽取与结构化：把非结构化文本转成 JSON/字段。
> - 分类/打标/情感分析等原本需要专门训练的 NLP 任务，用提示即可零样本/少样本完成。
> - Agent 的"大脑"：负责规划、决策、调用工具。

## 适用边界

**适合使用**

- 语言相关、容忍一定模糊性、需要泛化和创造性的任务
- 长尾、多任务场景，规则难以穷举时
- 作为 Agent/工作流的推理与编排核心

**不适合使用**

- 要求 100% 准确、可审计的事实性输出（未经外部核验时）
- 精确数值计算、强逻辑约束满足（应交给计算器/求解器/代码）
- 对延迟、成本极敏感且规则简单的场景（传统方法更划算）
- 涉及最新/私有数据而未接入检索或微调时

## 常见误区

- 以为它"理解"了含义——它是在做概率续写，不保证真实。
- 把它当数据库/搜索引擎——它会编造看似合理的答案（幻觉）。
- 认为"上下文塞得越多越好"——存在长度上限、成本上升和"迷失在中间"。
- 混淆训练与推理——普通调用不会让模型"记住"或"学会"新东西。
- 认为提示工程能弥补一切——上下文只能激活已有能力，无法凭空创造权重里没有的知识。

## 我的结论

> LLM 的正确心智模型是"一个知识渊博但会一本正经胡说、且不会自己查证的通用文本生成器"。
> - **该用它**：任务偏语言、能容忍不确定、需要泛化或创造，或作为 Agent 的推理中枢。
> - **不该单独用它**：需要精确、可核验的事实或强逻辑/数值保证时，必须外挂检索（RAG）、工具或校验环节。
> 工程上的关键不是"信不信任模型"，而是"用上下文和工具把它的能力约束、引导、核验到可用为止"。
