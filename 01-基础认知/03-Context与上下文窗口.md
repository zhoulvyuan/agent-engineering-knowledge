# Context / 上下文

> **上级**：[01-基础认知](README.md) ｜ **依赖**：LLM / 大语言模型、Token

## 一句话定义

> Context 是模型在某一次推理时实际"看得见"的全部输入——system prompt、对话历史、检索资料、工具返回等拼成的那串 token；它是模型做出当前回答的唯一依据。

## 解决的问题

> LLM 的权重在推理时是冻结的，不会"记住"上一轮说过什么，也不知道任何私有/最新信息。
> 要让它针对具体任务、具体对话、具体资料作答，唯一的办法就是把这些信息**放进输入里**——这就是 context。没有 context 机制，模型每次都只能"凭空"回答，无法多轮对话、无法基于资料、无法扮演角色。

### Context 是什么

Context（上下文）就是你在一次调用里喂给模型的**完整输入 token 序列**。它通常由几部分拼接而成：system prompt（角色与规则）+ 对话历史（之前的 user/assistant 轮次）+ 当前问题 + 可选的检索片段/工具结果/示例。模型没有"记忆",每一次推理都只基于这一次传入的 context；换句话说，**模型此刻知道什么，完全由 context 决定**。

### 上下文窗口是什么

上下文窗口（context window）是模型架构决定的、**一次推理能容纳的 token 数量上限**（如 8K、128K、1M）。关键点：
- 它是**输入 + 输出共享**的预算，不是只限制输入。
- 超出窗口的内容要么报错、要么被截断（丢最早的历史）。
- 窗口 ≠ 有效利用：窗口越大能塞越多，但存在"迷失在中间"（lost in the middle，长文中段信息易被忽略）、注意力稀释、成本和延迟上升等问题。
- 所以"窗口大小"是物理上限，"把什么放进去、怎么放"才是真正的工程问题。

### 为什么上下文管理成为 Agent 的核心问题

Agent 要多轮交互、调用工具、读取大量资料、长期执行任务，而这些信息会迅速**超过有限的上下文窗口**，且每个 token 都有成本和注意力代价。于是必须主动管理 context：
- **装什么**：只放当前步骤真正相关的信息（相关性筛选、RAG 检索）。
- **怎么压**：历史摘要、滚动窗口、工具结果裁剪，避免无关内容挤占预算。
- **放哪里/顺序**：重要信息放在首尾（规避 lost in the middle）。
- **外部化**：把放不下的东西转移到外部存储（memory / 向量库 / 文件），需要时再取回。
这些决策直接决定 Agent 的准确率、成本和能否完成长任务——所以"上下文工程（context engineering）"被认为是 Agent 的核心能力。

### Context 与 Memory 的区别

| 维度 | Context（上下文） | Memory（记忆） |
| --- | --- | --- |
| 本质 | 当前这次推理的输入 token | 外部持久化的信息存储 |
| 生命周期 | 一次调用内，用完即逝 | 跨会话长期保留 |
| 容量 | 受窗口上限限制 | 理论无限（数据库/向量库/文件） |
| 模型能否直接"看见" | 能，直接参与计算 | 不能，必须先检索并注入到 context 才生效 |
| 作用 | 决定模型"此刻知道什么" | 决定"下次能把什么再捞回来" |

一句话：Memory 是仓库，Context 是你每次搬到桌面上的那一小堆东西；Memory 里的信息只有被取出来、拼进 Context，才会真正影响模型的回答。

## 核心内容

- **构成**：context = system + 历史 + 当前输入 + 检索/工具/示例，全部以 token 计量，共享窗口预算。
- **无状态本质**：LLM 调用是无状态的，"多轮对话"是靠每次把历史重新塞进 context 模拟出来的。
- **窗口上限**：由模型决定（8K~1M+），输入输出共用；超限需截断/摘要。
- **lost in the middle**：信息放在上下文中段最容易被忽略，首尾最被关注。
- **上下文工程手段**：RAG 检索、历史摘要、滑动窗口、结构化/分段、重要信息置顶置尾、外部记忆。
- **与 token 的关系**：context 管理本质就是在有限 token 预算下做"信息取舍"的最优化。

## 典型工程场景

> - 多轮对话：维护并裁剪对话历史。
> - RAG：把检索到的资料片段注入 context 让模型基于事实作答。
> - 长文档处理：分块 + 摘要，避免超窗口。
> - Agent 任务：工具结果回填、历史压缩、长任务的状态管理。
> - 角色/规则设定：用 system prompt 固定行为。

## 适用边界

**适合使用**

- 需要模型基于特定对话、资料、角色、工具结果作答时
- 临时注入最新/私有信息（无需重新训练）
- 少样本示例引导输出格式

**不适合使用**

- 想让模型"永久学会"新知识/技能（应微调，而非塞 context）
- 需要跨会话长期记忆（应用 Memory 外部存储）
- 信息量远超窗口且无法有效筛选时（硬塞只会稀释注意力、涨成本）

## 常见误区

- 以为模型有"记忆"——其实每轮都靠重新传入历史模拟。
- 以为上下文窗口只限制输入——输入输出共享预算。
- 以为"把资料全塞进去就行"——会 lost in the middle、注意力稀释、成本飙升。
- 混淆 context 与 memory——memory 里的信息不检索进 context 就不起作用。
- 以为增大窗口能替代检索/摘要——大窗口仍需做信息取舍。

## 我的结论

> Context 是模型"此刻的全部认知边界"：它知道的、能用的，全在这串 token 里，之外一概不知。
> - **该用它**：注入当前任务所需的对话、资料、规则、工具结果——这是让通用模型干具体活的唯一入口。
> - **该管它**：窗口有限且每 token 有成本，所以要筛相关、压历史、重要信息置首尾、放不下的外部化。
> - **别误用**：想要"永久能力"去微调，想要"长期记忆"去建 memory，别指望往 context 里硬塞。
> 心智模型：context 是模型的"工作台",memory 是"仓库",上下文工程就是决定每次往工作台上摆哪些东西、怎么摆。
