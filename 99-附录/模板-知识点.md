## 使用说明

### 状态标记

| 标记 | 含义 |
| --- | --- |
| ⚪ | 未开始 |
| 🔴 | 不理解 |
| 🟡 | 理解中 |
| 🟢 | 已掌握 |
| 🔵 | 已实践 |

> V1 阶段不要急于给所有节点标记"已掌握"。状态的意义是**帮助识别知识缺口**。

### 学习深度

| 级别 | 含义 |
| --- | --- |
| A | 深入掌握 |
| B | 能够应用 |
| C | 理解概念 |
| D | 当前阶段暂不投入 |

### 三条写作原则

1. **写判断，不写定义。** "我的结论"一节是文件的核心价值所在。
2. **写边界。** "什么时候不该用"比"是什么"更重要。
3. **写缺口。** 不懂的地方明确写出来，这比假装懂了有价值得多。

### 沉淀流程

```text
知识地图发现缺口
   ↓
开一个专题会话探索（聊天负责探索）
   ↓
形成自己的结论
   ↓
回填到对应的知识点文件（本文件负责沉淀）
   ↓
更新知识地图的状态看板
```

> **聊天负责探索，文件负责沉淀。** 不要把所有聊天内容直接复制进来。

> **执行时不要凭记忆走上面的流程**，直接用
> [`会话回填模板.md`](会话回填模板.md) 里可复制的 prompt —— 它把
> "开头先读、中间探索、收尾写回"固化了下来，并包含收尾检查清单和四条纪律。
