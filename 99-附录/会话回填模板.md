# 会话回填模板

> **用途**：把一次"聊天式学习"的成果，沉淀回知识点文件。
>
> **核心纪律**：**每场会话必须以一个写回动作结束。** 没有写回动作的会话，
> 价值约等于零——那种"感觉学到了"会在 48 小时内蒸发。

---

## 0. 为什么需要这个模板

知识库的运行原则是：

```text
聊天负责探索，文件负责沉淀
```

但这句话只说了**分工**，没说**交接动作**。实践中的失败几乎都发生在交接这一步：
聊得很投入，散场时没有回填，两周后连"聊过什么"都想不起来。

本模板把交接动作**固化成一个可直接复制的 prompt**，避免每次现想、也避免漏掉关键纪律。

---

## 1. 三段式会话流程

| 阶段 | 目的 | 关键动作 |
| --- | --- | --- |
| ① 开头 | **防止重复讨论** | 让 AI 先读知识地图和目标文件，识别还缺什么 |
| ② 中间 | 探索 | 追问、要对比、要反例、要边界 |
| ③ 收尾 | **写回沉淀** | 按模板回填文件 + 同步看板 + 留空「我的结论」 |

> 三段里**只有 ③ 是不能省的**。① 和 ② 做得好是效率问题，③ 不做是无效问题。

---

## 2. 可直接复制的 Prompt

### 2.1 开头：先读，再规划

```text
我要学：<知识点名称>
目标文件：<域目录>/<文件名>.md

请先读「知识地图.md」和上面这个目标文件，然后只做三件事，不要展开讲解：

1. 列出该文件「待回答的问题」里，哪些还没有答案
2. 检查它「依赖」的前置知识点，指出以下三种情况（都是阻塞）：
   - 状态标记为 ⚪ 或 🔴 的
   - 状态是 🟡 但正文内容为空的（隐形阻塞，状态标记在撒谎）
   - 「待回答的问题」尚未回答完的
3. 给出你建议的学习顺序和理由

等我确认顺序后我们再开始。
```

**为什么强调"不要展开讲解"**：直接开讲会让会话失去焦点，而第 2 步
（前置知识有缺口）往往才是真正该先补的东西。

### 2.2 中间：探索用的追问句式

中间没有固定 prompt，但有几类问法特别有效——它们都指向知识库里最重要的
「适用边界」和「常见误区」两节：

| 想问什么 | 怎么问 |
| --- | --- |
| 划清概念边界 | "这两个概念的区别是什么？给我一个**会让人混淆的具体例子**。" |
| 找到适用边界 | "什么情况下**不该**用它？" |
| 验证是否真懂 | "给我一个**反例**：什么信号说明我选错了方案？" |
| 连接已有经验 | "在我的 Java 技术栈里，通常怎么实现？有什么既有能力可以复用？" |
| 暴露误区 | "关于这个概念，最常见的三个误解是什么？" |
| 防止浅层理解 | "如果我只记住一句话，应该记住哪句？为什么？" |

### 2.3 收尾：写回（**最关键，不要省**）

```text
本次会话到此为止，请做一次回填。

目标文件：<路径>

按「99-附录/模板-知识点.md」的结构，把本次讨论的结论写入该文件。

【需要你填写的】
- 一句话定义
- 解决的问题
- 核心内容
- 与其他知识的关系（上游 / 下游 / 易混淆）
- 典型工程场景
- 适用边界（适合 / 不适合，两栏都要有内容）
- 常见误区
- 待解决问题（把本次没聊透的部分写进去，作为下次会话的入口）

【需要你留空的】
- 「我的结论」—— 这一节我自己写，你不要代笔

【另外】
- 把文件头部的「更新」日期改为今天
- 「待回答的问题」中已解决的改为 [x]，但不要删除任何条目
- 状态标记先不要改，由我决定
- 在文件的「更新记录」里加一行本次会话的日期与主题
- 最后同步更新「知识地图.md」第 2 节看板中对应的那一行
```

**三条最容易被忽略、但最重要的约束**：

1. **「我的结论」留空** —— 见第 4 节纪律二。
2. **不要删除「待回答的问题」条目** —— 只把已解决的改为 `[x]`。
   这份清单本身就是你的学习轨迹，删掉就没了。
3. **状态不自动升级** —— 由你判断，见第 5 节门槛。

### 2.4 域收敛：每完成一个域跑一次

当一个域的所有知识点都填完后，单独开一次会话来**收敛**。这是防止
"知识点孤立"和"矛盾累积"的唯一手段：

```text
我已完成「<域名称>」这个域的学习。

请通读该域下所有知识点文件，做一次收敛检查，**只报告问题，不要修改任何文件**：

1. 找出互相**矛盾**的结论
2. 找出**重复定义**的概念
3. 找出**语义漂移**的术语（同一个词在不同文件里含义不同）
4. 检查是否与「知识地图.md」的「结构决策记录」冲突
5. 尝试用一段话概括这个域的核心，看这些知识点能不能串起来

最后告诉我：这个域还有哪些明显缺口。
```

> **"只报告问题，不要修改任何文件"** 是必须的。收敛检查会涉及跨文件的
> 判断，让 AI 自动改容易把原本正确的表述也改掉。由你决定改什么。

---

## 3. 收尾检查清单

每次会话结束，逐项确认：

- [ ] 「待回答的问题」已更新（已解决的标 `[x]`，**未删除**）
- [ ] 「核心内容」有实质内容，不是复述定义
- [ ] 「适用边界」的 **"不适合"一栏非空** ← 最常被跳过的一栏
- [ ] 「常见误区」至少有一条
- [ ] 「我的结论」已由**我本人**填写 ← 不能是 AI 写的
- [ ] 「待解决问题」已写下，作为下次会话的入口
- [ ] 文件头部「更新」日期已改
- [ ] 「知识地图.md」第 2 节看板对应行已同步
- [ ] 状态是否升级已由我判断

## 4. 四条不能破的纪律

### 纪律一：每场会话必须以写回动作结束

没有例外。哪怕这次只聊明白了一个小问题，也要写回去。
"下次一起整理"等于永远不会整理。

### 纪律二：「我的结论」必须自己写

这是知识库质量的**分水岭**。

AI 给的永远是**素材和选项**；「我的结论」必须是**你自己的判断**。
如果让 AI 代笔，你攒下的会是一份看着很专业、但你并不掌握的文档——
这**比空白更危险**，因为它会让你误以为自己会了。

> 检验方法：过一个月回看「我的结论」，如果你无法在不看其他章节的情况下
> 为它辩护，那它就白写了。

### 纪律三：一次会话只推一个知识点

想一次聊完"Agent Loop + Memory + Planning"，结果一定是三份都写得很浅。

### 纪律四：状态升级要过门槛

见第 5 节。聊过一次不等于掌握。

---

## 5. 状态升级门槛

这是防止「状态通胀」的机制——是本知识库最容易被自己欺骗的地方。

| 变化 | 门槛 |
| --- | --- |
| ⚪ → 🟡 | 开始接触，有了初步印象。**门槛很低，聊过一次就可以** |
| 🟡 → 🟢 | 能**不看资料讲清楚**，且能说出**什么时候不该用**。两个条件都要满足 |
| 🟢 → 🔵 | 在**真实项目**里用过，并能说出实际踩到的坑 |
| 任何 → 🔴 | 发现之前的理解是错的 |

> **关于 🔴**：它不是退步，而是**进步的证据**——说明你之前以为自己懂了，
> 现在发现边界在哪。知识库里出现 🔴 是健康的信号，不要回避它。
>
> 尤其注意：`Agent Loop` 和 `Workflow vs Agent` 目前就是 🔴，
> 它们是你最真实的缺口，值得优先攻克。

---

## 6. 会话粒度建议

| 情况 | 建议 |
| --- | --- |
| 一个知识点 | ≈ 一次会话（30~60 分钟），这是默认粒度 |
| 会话超过 2 小时 | 大概率在同时聊多个知识点，拆开 |
| 知识点很小（如"Token 是什么"） | 可以合并到相邻知识点一起聊 |
| 知识点标 `深度 D`（暂不投入） | 不用开会话，保持 ⚪ |

---

## 7. 一条反纪律：不要把会话原文粘进文件

知识库不是聊天记录仓库。

**要粘的是结论，不是过程。** 探索过程留在会话里，文件只放你消化后的判断。
判断标准：如果一段内容三个月后你自己不会再读第二遍，就不要放进文件。
